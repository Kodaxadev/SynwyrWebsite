THE DIFFERENCE

Not a bigger
script button.

Most agent integrations give a model a remote command surface and hope the result is right. Synwyr is being built around a harder requirement: inspect what exists, make bounded changes, see what changed, and prove whether the result is valid.

01

Structured operations

Typed editor-native actions are the normal path. Arbitrary host-code execution is an explicit escape hatch, not the architecture.

02

Observable state

Stable identity, scene revisions, capability discovery, machine-readable inspection, and visual evidence give the agent concrete state to reason against.

03

Verified transactions

Changes happen inside explicit transactions. Rollback is checked against pre-edit state instead of being assumed successful.

THE CLOSED LOOP

Intelligence needs feedback.

An agent that cannot re-observe the world after acting is guessing. Synwyr turns 3D work into a repeatable perception → action → evidence cycle.

IDENTITYObjects survive names.

Persistent IDs and revision-scoped topology references prevent transient labels and indices from becoming identity.

CONCURRENCYStale state fails closed.

Mutations can carry an expected revision. If the editor changed after inspection, the stale edit is rejected instead of guessed through.

THREADINGRespect the editor.

Host APIs stay on their required editor thread. Transport plumbing never gets permission to mutate Blender or Unity behind the application.
