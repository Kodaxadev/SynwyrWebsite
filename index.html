HOW IT WORKS

A closed loop, not a blind command.

Synwyr makes the agent re-check the world after every meaningful action. That is the difference between “the API returned success” and “the result is actually right.”

01PERCEPTION

See the scene.

Capture scene state, IDs, revisions, and visual evidence from the connected 3D editor.

scene.snapshotviewport.capture
02ACTION

Make the change.

Run a bounded, editor-native operation against the same scene revision the agent inspected.

transaction.beginmesh.modify
03VERIFICATION

Prove the result.

Inspect again, compare before/after state, and either commit the result or roll it back safely.

mesh.validatecommit / rollback
AI AGENT→SYNWYR→BLENDER / UNITY→NEW EVIDENCE→DECISION
WHY SYNWYR

What it claims is what it shows.

Synwyr is not just trying to expose controls. It is trying to give an autonomous model enough spatial context and recovery guarantees to work responsibly inside a real 3D project.

Read the architecture ↗

Persistent identity

The agent reasons about real objects and revisions, not fragile labels or whatever the model last guessed.

Structured editor actions

Rollback you can trust

CURRENT STATE

Foundation first. Then breadth.

Synwyr is active engineering work, not vapor. Blender has the strongest closed-loop implementation today. Unity parity and broader production-scene coverage are still being pushed forward and verified.
